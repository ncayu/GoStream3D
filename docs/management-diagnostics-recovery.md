# 管理诊断、容量测试与项目恢复

2026-10-04。本轮扩展上一轮逐路 JPEG 测量。Windows 传输仍为 JPEG/WebSocket，未新增视频编码。

## 平台监控

“平台监控 → GPU 与显存”显示每块可读取的 NVIDIA GPU 的使用率、视频编码器使用率、已用 / 总显存。使用驱动自带 `nvidia-smi`，与服务器监控共用采样周期；查询超时 2 秒，后台缓存结果，页面请求不额外启动采样进程。指标包含其他程序占用，浏览器自动选择 GPU，因此不把显卡占用强行归到某一路。其他厂商、驱动缺失、不可读取的单项指标显示不可用，不能当成 0。查询字段定义见 [NVIDIA 官方文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html)。

该区域同时展示近 1 小时的 GPU 使用率趋势，纵轴固定为 0–100%，悬停可查看时间与百分比。多块显卡以 UUID 区分，各自显示一条曲线；采样不可用或显卡暂时消失时保留数据缺口，不连接缺失区间，也不记为 0%。趋势复用服务器采样周期（默认 30 秒，可在后台设置调整），历史保存在服务器内存，服务重启后重新积累。

“逐路画面性能”增加：

- 页面回调 FPS：统计应用 `requestAnimationFrame` 回调的不同时间戳，每 2 秒读取；不添加自己的动画循环。它是应用更新的参考，不等于 GPU 物理呈现或业务场景完成绘制的帧率，非 rAF 场景可能没有样本。
- 发送 FPS：服务器成功写入 JPEG 的速率，包含同一实例所有连接的发送次数；通常每个独立实例只有一个观看连接。
- 输入至后续画面：观看端每最多 500 毫秒给真实操作附加采样序号。从发送操作到 CDP 转发后交付的后续帧在 Canvas 绘制完成的参考耗时，包含输入队列、采集与往返传输。CPU 输入在实际发出 CDP 请求后才关联帧，避免把队列接收当成发送完成。服务端用发送帧记录验证回执、拒绝重复和异常值；观看端最多保留 64 个、30 秒内的待测序号。没有近期操作时显示“等待操作”。

后续帧不能证明应用已经处理该操作并生成对应视觉变化；`drawImage` 返回也不证明显示器呈现。因此输入指标不能作为业务输入响应的精确保证。准确测量业务响应需要场景事件标记或视觉变化探针。

## 实际场景容量测试

入口：“后台设置 → 实际场景容量测试”。选择已保存项目、最多 1–10 路、每级 30–120 秒及达标 FPS（不得超过项目目标）。启动前需要足够空闲通道；可先在链接列表停止无须保持运行的项目。测试不会抢占或回收预加载。

测试使用原 URL、渲染方式、分辨率、目标帧率和就绪标记，生成独立临时浏览器目录。自适应项目固定使用 1920×1080。原项目配置、链接和已有观看会话保留。GPU 副本采用持续动画策略，且与其他实例共用当前 GPU 总预算、通道池和软件 CPU 配额。加载原页面会产生其正常网络请求，所以应选择适合重复打开的场景。

从 1 路逐级增加。每一级等待所有副本就绪，再预热 10 秒，按一秒窗口统计本机 WebSocket 接收并成功 JPEG 解码的帧数。每一路至少 90% 的窗口达到所填 FPS 才通过；任何一路失败时停止继续加压。报告包含平均 FPS、P10 FPS、页面回调 / 采集 FPS、写入耗时、字节率、每级结束的 GPU / 显存样本、其他活动实例数，以及项目、阈值、GPU 预算和 CPU 配额。配置在测试中变化时报告失败，需要重测。

已通过的最大路数是本次测试范围内的服务器建议值，不是硬件自动识别上限。测试使用服务器回环网络和 Go JPEG 解码器，未包含远端网络、浏览器绘制、业务操作和镜头切换。持续动画、静态页面和不同复杂度场景的结果可能不同；静态画面未更新也可能无法通过。不要仅凭一个测试结果把总通道数直接增加到 100。

建议维护时分别测试最重的持续动画场景与正常场景，并在目标客户端观察逐路显示 FPS 与输入参考耗时，保留余量。测试会临时增加负载，结束、失败和取消后停止副本并删除临时浏览器目录；清理失败会报告错误并保留 Worker 的端口所有权，避免把未释放资源当成空闲。程序退出会取消正在运行的测试。

最近完成的报告保存为会话目录旁的 `capacity-report.json`，后台可下载 JSON。报告保留具体条件与时间，不自动更新通道配额；中断后的旧报告提示重新测试。

## 项目 JSON 备份与恢复

启动时按条解析和校验项目数组。单条数据损坏、字段错误或重复标识只跳过该条，合法项目仍加载。重复标识保留第一条合法记录。整个 JSON 无法解析时，管理后台可以启动，但项目写入受到保护，避免空列表覆盖原文件。

检测到损坏会先将完整原始字节存到 `<session-store>.backups/sessions-damaged-*.json`，成功保留原文后才继续启动。后台显示记录编号、标识与错误，并提供备份列表。文件访问或原文保存失败仍作为启动错误处理，防止无备份覆盖。

每次项目配置变化，保存修改前与即将提交的健康状态，保留最近 20 份自动备份；即使只创建过一个项目，也有包含该项目的自动副本。手动备份和损坏原文不自动删除。文件使用受限权限、同步写入与临时文件替换；备份保存失败会阻止项目文件替换。未实际变更的保存不新建重复自动副本。

入口：“后台设置 → 项目备份与恢复”。

1. 创建手动备份，或选择现有自动 / 手动备份。
2. 预览可恢复项目、已存在项目数及不合法记录数。
3. 点击“恢复这些缺失项目”，服务端重新校验备份摘要，只添加缺失的合法项目。

恢复保留原项目标识与观看地址，不覆盖现有配置，不删除现有项目，也不影响其观看实例。恢复的项目统一停止渲染，管理员可在链接列表逐个启动。原始加载问题在本次程序运行中保留作诊断，正常数据文件在下次启动重新检查。

备份仅覆盖项目定义，不含浏览器目录、CPU / GPU / 通道设置、管理员凭据或资源缓存。全文件不可解析且没有健康备份时，不能凭空恢复项目；请保留损坏原文，人工修复文件后重启。恢复功能不是对现有项目的历史版本覆盖功能。

## 接口与验证

所有管理接口需要管理员认证：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/admin/monitor` | GPU / 显存与已有整机资源样本 |
| GET | `/api/v1/admin/performance` | 逐路帧率与输入参考耗时 |
| GET / POST | `/api/v1/admin/capacity` | 查看报告 / 启动后台容量测试 |
| POST | `/api/v1/admin/capacity/cancel` | 取消并清理测试 |
| GET | `/api/v1/admin/store` | 加载问题与备份列表 |
| POST | `/api/v1/admin/store/backup` | 创建手动备份 |
| POST | `/api/v1/admin/store/preview` | 用 `backup_id` 预览 |
| POST | `/api/v1/admin/store/restore` | 用 `backup_id` 和预览返回的 `digest` 恢复缺失项目 |

回归覆盖坏记录隔离、损坏原文逐字节保留、最新状态备份、全文件损坏写保护、恢复不覆盖现有定义、暂停恢复、路径与摘要校验、接口认证、容量阈值与最慢路判定、取消与持久化、输入帧关联、GPU 多卡与不可用数据。

真实 Edge / Chrome 的小型动画夹具验证两路采样，以及取消后 Worker、端口、临时目录的清理。它只验证机制，不作为复杂 3D 场景容量报告。前端检查包含桌面 / 手机布局及备份预览、恢复、容量启动和取消。界面检查使用隔离模拟后台，未修改正在运行的服务或保存项目。

```powershell
go test ./cmd/server ./internal/...
npm --prefix web test
npm --prefix web run build
```
