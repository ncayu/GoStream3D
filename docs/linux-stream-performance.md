# Linux GPU / CPU 逐路画面性能

交付版本：20261010-002003。实测服务器：192.168.1.100，WSL2 Ubuntu / NVIDIA GeForce RTX 3050 Ti Laptop。

Linux WebRTC 观看页现在每 3 秒读取一次视频接收统计，回传到网关；管理后台“平台监控 → 逐路画面性能”同步显示各条观看连接。NVIDIA / Intel GPU 与 CPU 使用相同的接收端统计，Windows JPEG 面板继续使用原测量方式。

## 可查看的指标

|指标|测量含义|
|---|---|
|项目 / 实例 / 观看端|网关按实际租用的 worker 绑定身份，多个观看端独立显示|
|目标 FPS|项目配置，不代表实测帧率|
|实收 FPS|采样区间收到完整视频帧数量 / 区间时长|
|显示 FPS|浏览器视频播放帧增量扣除播放丢帧后的速率|
|分辨率 / 编码|观看端收到的视频实际宽高、H.264 / VP8 等编码|
|视频码率|接收到的视频 RTP 载荷增量，单位 Mbps，包含重传载荷，未计入所有网络协议开销|
|解码耗时|区间解码耗时增量 / 区间成功解码帧数，单位 ms|
|播放缓冲|区间 jitter buffer 耗时增量 / 出缓冲的帧数，单位 ms|
|网络往返 RTT|选中的 ICE candidate pair 当前往返时间，不是输入到画面的延迟|
|丢包 / 解码丢帧|区间增量，不能直接相加作为一项丢帧指标|
|样本时长|本次观看端采样区间长度|

统计口径依照 [W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/)。这些是观看端反馈，不直接测量服务端截图、硬件编码耗时或 GPU 物理呈现，也不能将整机 GPU 占用直接归属于某一路。

## 使用与生命周期

升级后，管理页及观看页均按 Ctrl+F5。打开观看链接，保持观看页可见约 6 秒，首个区间样本建立后，后台即可看到数据。第一份统计仅建立计数器基线，避免把从连接开始累计的数据误当作当前速率。

- 真实零丢包、零 RTT 等仍显示 0；浏览器不支持的字段显示“—”。区间没有成功解码帧时，解码耗时显示“—”。
- 隐藏观看页暂停采样；超过 10 秒没有有效反馈，后台清除旧数据并显示采样过期。
- 同一项目的多路独立实例、同一实例的多个观看连接均独立记录；断开连接后移除对应行。
- 重连、SSRC 更换及计数器复位时重新建立基线；不将旧连接的帧数和字节数混入新连接。
- 网关校验消息大小、数值范围、采样时长并限制回传频率。项目和实例身份由服务器分配，观看端不能指定其他实例；性能消息由网关截获，不转发给 Neko。
- “GPU 总帧率预算”仍属于 Windows JPEG 的调度功能；Linux 面板显示 WebRTC 测量，不据此声称已支持相同调度器。

## 验证

自动测试覆盖区间帧率/码率计算、解码和缓冲单位换算、真实零与缺失字段、首份基线、SSRC 变化、计数器重置、观看端隔离、过期数据、非法反馈，以及性能消息截获后正常信令继续转发。管理性能接口仍需管理员认证。

实机验证结果随镜像包 `STREAM_PERFORMANCE_VERIFICATION.json` 与 `stream-performance-proof/` 交付；容器运行回归写入 `VERIFICATION.json`。具体 FPS/延迟为当次场景样本，不保证其他场景相同结果。

本轮简单 WebGL 测试页面实测：GPU 1080p 首个区间实收 30.00 FPS、显示 29.68 FPS、平均解码 0.59 ms、缓冲 6.00 ms、RTT 1 ms；CPU 1080p / VP8 实收 30.33 FPS、显示 30.00 FPS、平均解码 3.12 ms、缓冲 7.36 ms。区间帧数除以时间可能略高于配置值，并不表示目标帧率被提高。这些仅验证测量链路，不能代替复杂园区的性能测试。

同时打开 GPU 1080p 与 720p 两条独立实例，两路显示分别约 29.67 与 29.68 FPS，身份和分辨率均正确；隐藏其中一路 13 秒，仅该路的旧样本被清除，另一路继续更新；恢复可见后重新采样，逐一关闭后对应行移除。GPU / CPU 观看端和管理页脚本错误均为 0。完整数据见随包 JSON。

真实 ThingJS 园区另开独立临时项目，1080p / H.264，预热 30 秒后拖动画面：一个区间实收 30.01 FPS、显示 27.34 FPS、视频载荷 16.42 Mbps、平均解码 1.02 ms、缓冲 134.70 ms、RTT 1 ms、区间丢包与接收端丢帧为 0，页面脚本错误为 0。面板实际显示“播放缓冲偏高”；后续截图区间的数值有所变化，应以各自时间样本为准。此次测量接入用于定位问题，不据此声称复杂园区帧率或延迟进一步改善。证据：`scene-browser-proof.json`、`scene-panel.png`、`scene-viewer.png`。
